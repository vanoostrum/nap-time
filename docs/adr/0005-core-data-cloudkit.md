# Core Data with NSPersistentCloudKitContainer, not SwiftData

Both parents must see and edit one family's data from two Apple IDs, with no server. That needs a CloudKit share (`CKShare`) on the shared database. Core Data with `NSPersistentCloudKitContainer` supports the private and shared databases and `CKShare`. SwiftData's CloudKit sync supports only the private database, and we found no Apple source that says iOS 27 changes this (checked 2026-11-13). So the family store is Core Data with `NSPersistentCloudKitContainer`, in the App Group container.

## Consequences

- The store code imports Core Data, so it cannot live in Core. It lives in a framework target, `NapTimeStore`, defined in `project.yml`. The app `NapTime` and the widget extension `NapTimeWidget` both link it, so the widget and the "awake" App Intent open the same family store in the App Group. `NapTimeStore` depends on Core. Core gets plain value types, and `NapTimeStore` maps them to and from managed objects.
- Sharing between two Apple IDs cannot be tested on the simulator. The first real test is on the two phones, with a build from Xcode, after the sharing ticket merges. TestFlight, after v1, tests it again against the production CloudKit environment.

The family store has two stores: the private store `NapTime.sqlite` and the shared store `NapTime-shared.sqlite`, with `databaseScope = .shared`. The family has one zone-wide `CKShare`, which the owner's first invite makes. Each new child and sleep goes into that share: on the owner's phone with `share(_:to:)`, on the partner's phone with `assign(_:to:)` to the shared store. If a move into the share fails, the store moves the child or sleep on the next store change. A sleep stays in the store of its child, because a relationship cannot cross stores. A partner's children from before joining stay in the partner's private store, on that phone only. Two phones can log overlapping sleeps for the same child before they sync. On every store change, a Core rule merges them into the sleep that started first, with the lowest id on a tie. That sleep starts at the earliest start and ends at the latest end of the ended sleeps. It runs only when every sleep in the group runs. The store updates that sleep and deletes the others. (CRAFT-50, 2026-11-16)
