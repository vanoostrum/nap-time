# A release starts by hand and waits for Theo's approval

A merge to `main` deploys nothing. The workflow `Release` (`.github/workflows/release.yml`) is the only way to production. It starts with `workflow_dispatch`, from `main` only, and its job uses the GitHub environment `testflight`. That environment has Theo as its required reviewer and holds the App Store Connect secrets, so no build reaches TestFlight until Theo clicks "Approve". An agent may start the workflow when Theo asks, but the job still waits for him. Production holds the family's real sleep log, and the production CloudKit schema cannot be undone (ADR 0011), so a person decides each release. The build number is the workflow's run number, and each release that uploads gets the tag `release/<build number>`. A re-run keeps the run number: it works when the upload failed, and a new run is needed when the upload already succeeded. (Theo, 2026-11-18)
