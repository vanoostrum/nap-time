# CI signs with automatic signing and an App Store Connect API key

The `Release` workflow signs with Xcode's automatic signing, authenticated by an App Store Connect API key with the Admin role, which lets Xcode use cloud-managed distribution certificates. There is no certificates repo and no `.p12` in the secrets. The key lives in the GitHub environment `testflight` as `ASC_KEY_ID`, `ASC_ISSUER_ID`, and `ASC_KEY_P8`, and never in the repo, the logs, or the workflow file. A run must not create a new development certificate, because a fresh runner has no local keys and the account allows only a few. The workflow checks the entitlements of the exported app: `aps-environment` is `production` and the iCloud container environment is `Production`, while `project.yml` keeps `development` for Debug builds. If automatic signing fails on a fresh runner, or creates a certificate on each run, a follow-up ticket switches to a distribution certificate and profiles as secrets in `testflight`. (2026-11-18)
