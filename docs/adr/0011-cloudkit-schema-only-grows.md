# The production CloudKit schema only grows

CloudKit cannot remove or rename a record type or a field once it is in the production schema, and the production database holds the family's real sleep log with no other backup. So a change to the Core Data model only adds entities or optional attributes. It never removes, renames, or retypes one, and never makes one required. Before a release that changes the model, Theo deploys the schema from development to production in the CloudKit Console. A Debug-only launch argument `--init-cloudkit-schema` fills the development schema first, with `initializeCloudKitSchema()` for both stores. The `Release` workflow compares `Store/NapTime.xcdatamodeld` with the newest release tag, and fails when the model changed and its input `schema_deployed` is not ticked. The first release has no release tag, so it counts as a model change. (2026-11-18)
