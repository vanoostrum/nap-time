# The production CloudKit schema only grows

CloudKit cannot remove or rename a record type or a field once it is in the production schema, and the production database holds the family's real sleep log with no other backup. So a change to the Core Data model only adds entities or optional attributes. It never removes, renames, or retypes one, and never makes one required. Before a release that changes the model, Theo deploys the schema from development to production in the CloudKit Console. A Debug-only launch argument `--init-cloudkit-schema` fills the development schema first, with `initializeCloudKitSchema()` for both stores. The `Release` workflow compares `Store/NapTime.xcdatamodeld` with the newest release tag from a run that had this check, and fails when the model changed and its input `schema_deployed` is not ticked. Until such a tag exists, the model counts as changed: the first releases ran before the check, and the production schema was never deployed.

The check runs in the first job of `Release`, before Theo's approval, so a forgotten tick fails at once. A run that had the check marks its release tag: an annotated tag whose message holds the line `schema-check: yes`. (2026-11-18)
