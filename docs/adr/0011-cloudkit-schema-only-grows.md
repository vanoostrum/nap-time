# The production CloudKit schema only grows

CloudKit cannot remove or rename a record type or a field once it is in the production schema, and the production database holds the family's real sleep log with no other backup. So a change to the Core Data model only adds entities or optional attributes. It never removes, renames, or retypes one, and never makes one required. Before a release that changes the model, Theo deploys the schema from development to production in the CloudKit Console. A Debug-only launch argument `--init-cloudkit-schema` fills the development schema first, with `initializeCloudKitSchema()` for both stores. Then it saves a throwaway zone-wide share in its own zone, and deletes the zone, because CloudKit adds the record type `cloudkit.share` only when a share is saved. Without it, sharing fails in production (2026-11-22).

No check in the `Release` workflow guards this step: Theo deploys the schema by hand, and a PR that changes the model says so. (2026-11-18; the release checkbox and its check were removed on 2026-11-26.)
